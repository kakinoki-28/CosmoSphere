# プログラムの説明
CosmoSphereは、Pythonで実装されたゲームプログラムです。
現在は技術デモの状態になります。

## ゲームの概要
「シューティング」×「格闘ゲーム」をテーマにした対戦型アクションゲームです。
プレイヤーは、ジャンプしたり跳ねたりする丸いキャラクターに乗って操作をします。

キャラクターは豊富な「射撃スキル」と「シールド」、そして１つだけ「近接攻撃」の手段を持っています。
- **「射撃スキル」** は 「近接攻撃」 に **強い** です<br>
ダメージを食らうと攻撃動作がリセットされます。近接攻撃は振りかぶりが長いので、遠い距離で振ると格好の的になります。
- **「シールド」** は「射撃スキル」に **強い** です<br>
シールドは、射撃スキルを跳ね返したり、無効化します。射撃された弾が速ければ速いほど、反射された弾に対処できなくなります。
- **「近接攻撃」** は「シールド」に **強い** です<br>
近接攻撃は、シールドを破壊できます。ずっとシールドを構えている相手には、素早く近づいて近接攻撃をお見舞いできます。

距離を保ちつつ「射撃スキル」で勝負しても良いですし、「シールド」を上手く使って相手のミスを誘発しても良し、相手の射撃スキルをかわして「近接攻撃」で一発逆転を狙うこともできます。

格闘ゲームとはまた一味違った駆け引きを是非楽しんでください！

## 実行方法

### 実行環境
- Python 3.13.1
- pygame 2.6.1 (SDL 2.28.4)
で動作することは確認済みです。

恐らくですが
- Python 3.x
- pygame 2.6.x
であれば問題なく動作します。

### 実行手順
Python で main.py を実行してください。
main.pyに対して、「True」もしくは「False」のコマンドライン引数を与えることが出来ます。
Trueを与えるとロールバック機能の動作の様子を見ることが出来ます。

### 操作方法
デフォルトでは以下の様に操作が出来ます。

＜キーボード操作＞
- ジャンプ：W
- 左右移動：A,D
- 台から降りる：S

- 射撃スキル１：J
- 射撃スキル２：K
- 射撃スキル３：L

- 近接攻撃：Space
- シールド展開：左Shift

<コントローラー><br>
このゲームはコントローラー操作にも対応しています。<br>
コントローラーを接続すると新しくキャラが追加されます。対戦を楽しみたい場合はコントローラーを接続してください。<br>
Xbox One Controllerでの動作を確認しております。デフォルトは以下の動作です。
- ジャンプ、左右移動、台から降りる：左スティック

- 射撃スキル１：Aボタン
- 射撃スキル２：Xボタン
- 射撃スキル３：Yボタン

- 近接攻撃：Bボタン, LBボタン, RBボタン
- シールド展開：LTボタン, RTボタン

## 動作説明

ファイル構成と特徴的な仕様については以下の通りです。

### ファイル構成

Pythonで書く目的の一つに、書くコード量自体は少なくなるというのがあり、当初は１ファイルで完結していました。<br>
しかし、ゲームが肥大化してくるとコード量も大きくなってきたので、MVCモデルを参考にしつつ以下のようにファイルを分割しています。

```
.
├──main.py
│   アプリケーション全体の実行を担当。
│   各種入力を管理して適切に分配する役割も担う。
│
├──game_manager.py
│   ゲームの全体の管理を担当。ロールバック機能付きも記述。
│   ゲームの実行やデータの保持、描画など各種機能への橋渡しの様な役割。
│
├──gamelogic.py
│   ゲームのロジックを担当。ゲーム内の動作はすべてここに記述。
│   （キャラ毎に分けることも検討中だが、循環参照の問題を解決できず）
│
├──gameconst.py
│   ゲームロジックの定数の管理・保持を担当。
│   バランス調整がしやすいようにゲームロジックから定数のみ分離している。
│
├──render.py
│   ゲームの描画を担当。
│   渡されたゲーム状況を元にゲーム画面を描画する処理のみを分離している。
│
├──input.py
│   入力の抽象化を担当。
│   キーボードやコントローラー、それら両方の入力を受け付ける場合でも正しくゲームが動作するように入力を調整する。
│
├──id_maker.py
│   キャラクターを識別するためのIDの生成を担当。
│   
│   （以下、pythonファイル以外の静的なファイル）
│
├──images/
│   各種画像
├──inputconfig.ini
│   入力設定の保存
└──Hammer_data.txt

```


### 入力遅延の削減
このゲームは毎秒64フレームの間隔で実行されます。しかし、描画FPSは毎秒240フレームを上限としており、ゲームの更新間隔とは別れています。また、入力の取得の間隔（ポーリングレート）は毎秒1000回を上限としています。以上の３つの処理は各スレッドで並列処理が行われます。<br>
こうした動作をするのは、処理負荷の増加やゲームロジックの破綻を防ぎつつ、入力遅延を感じにくくするためです。


### ロールバック機能の搭載
コマンドライン引数でTrueという文字列を渡すとロールバック機能を試すことが出来ます。将来的に通信対戦の実装を考えており、入力遅延を隠蔽するために遅延した入力が届くとロールバックするような仕様を実装しました。<br>
別作品（完成しなかったため非公開なのですが…）を制作していた時、サーバーにゲーム処理を任せたところ入力遅延が酷かったため、以降ロールバック機能を搭載するようになりました。

### 特殊なロールバック機能
ロールバックの動作の中でゲームの状況（ステート）を各フレームごとに保持する必要があるのですが、Pythonはクラスの再帰的なコピー（deepcopy）が非常に遅いという欠点がありました。<br>
標準ライブラリの直列化機能であるpickleを利用することで多少改善したのですが、それでも1フレーム（1/64≒16ms）内で各ステートをコピーする処理が間に合わないという問題に直面しました。<br>
そこで、1フレーム前,2フレーム前,4フレーム前...のように2の累乗の前のステートだけ保持し、必要な時に更新するという処理にしています。ステートを更新する処理はコピー処理程のオーバーヘッドがなかったためこのような仕様になっています。
